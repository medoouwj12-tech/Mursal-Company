# مرسال لإدارة الطلبات

تطبيق تشغيل عربي RTL لشركة مرسال: تسجيل الطلبات، استقبالها من المناديب، إسناد ذري، وتتبع مراحل التسليم.

## التقنية والبنية

- Next.js App Router + TypeScript + Tailwind CSS + Framer Motion.
- Supabase Auth وPostgreSQL وRealtime مع RLS.
- `supabase/migrations/0001_initial.sql`: الملفات والجداول والسياسات والدوال الذرية.
- `app/page.tsx`: تجربة الدخول ومساحات المدير والكول سنتر والمندوب.
- `app/api/admin/users`: إنشاء وتعطيل وحذف المستخدمين وتغيير كلمات المرور، بصلاحية service role محفوظة على الخادم.
- `app/api/push` و`public/sw.js`: اشتراكات وإرسال Web Push عند وصول طلب جديد.
- تسويات المندوبين اليومية: مجموع رسوم توصيل الطلبات المسلّمة، نسبة المكتب، وصافي مستحق المندوب. يضبط المدير النسبة من الإعدادات، وتُحفظ في `app_settings`.

## التشغيل المحلي

1. ثبّت Node.js 20+ وSupabase CLI، وأنشئ مشروع Supabase.
2. انسخ `.env.example` إلى `.env.local`، ثم أدخل `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY`.
3. سجّل الدخول إلى Supabase CLI واربط المشروع (`supabase login` ثم `supabase link --project-ref ...`).
4. نفّذ المخطط: `npm run db:push`.
5. أنشئ مفاتيح `SUPABASE_SERVICE_ROLE_KEY` في `.env.local` ثم شغّل `npm run db:seed` لإنشاء 1 مدير و5 كول سنتر و20 مندوبًا والخدمات.
6. `npm install` ثم `npm run dev` وافتح `http://localhost:3000`.

### حسابات البيانات التجريبية

- المدير: `admin` / `MersalAdmin2026!`
- الكول سنتر: `call1` إلى `call5` / `CallCenter2026!`
- المناديب: `courier01` إلى `courier20` / `Courier2026!`

غيّر كلمات المرور قبل التشغيل الفعلي. `SUPABASE_SERVICE_ROLE_KEY` سرّ خادمي، ولا تضعه في متغير يبدأ بـ`NEXT_PUBLIC_`.

## الاستلام الذري والتزامن

العميل يستدعي `claim_order(order_id)`. داخل PostgreSQL تتحقق الدالة من الدور والتوفر وسعة المندوب، ثم تنفّذ تحديثًا مشروطًا على الطلب الذي ما زال `pending`. تحديث الصف يقفل صف الطلب، ويضمن أن محاولة واحدة فقط تُرجع صفًا ناجحًا؛ المحاولات الأخرى تتلقى رسالة «الطلب اتاخد من مندوب تاني». قفل ملف المندوب قبل فحص السعة يمنع تجاوز حد الطلب النشط عند استلام طلبين مختلفين في وقت واحد.

شغّل اختبار العشرين مندوبًا على مشروع تجريبي بعد تطبيق المخطط وزرع الحسابات:

```sh
npm run test:race
```

ينشئ الاختبار طلبًا تجريبيًا، يسجل دخول الحسابات العشرين، يطلق RPC بالتوازي، يتحقق من وجود فائز واحد، ثم يحذف الطلب. يحتاج مفاتيح Supabase نفسها في البيئة.

## Push Notifications وPWA

يعمل التطبيق كتطبيق ويب قابل للتثبيت، ويخزّن shell الأساسي للتصفح عند انقطاع الاتصال. لتشغيل Push:

1. أنشئ زوج مفاتيح VAPID باستخدام `npx web-push generate-vapid-keys`.
2. أضف `NEXT_PUBLIC_VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` و`VAPID_SUBJECT=mailto:...` إلى بيئة الخادم، وأعد تشغيل التطبيق.
3. سجّل المندوب دخوله واضغط «تفعيل إشعارات الطلبات» واسمح للتنبيهات في المتصفح.

يلزم HTTPS للإشعارات خارج localhost. الطلبات المتاحة وتغيّرها تصل أيضًا عبر Supabase Realtime، ويعاد الاتصال تلقائيًا.

## الأمان والنشر

- RLS يحصر الطلبات على منشئها أو مندوبها أو المدير، ويعرض الطلبات الجديدة للمناديب المتاحين فقط.
- إنشاء المستخدمين وتغيير كلمات المرور يستخدم Supabase Admin API من route خادمي بعد التحقق من جلسة المدير.
- حوّل الـusername داخليًا إلى `${username}@mursal.app`، بينما Supabase Auth يخزن كلمات المرور باستخدام آلية التشفير الخاصة به.
- انشر Next.js على Vercel أو خادم Node، واضبط متغيرات البيئة المذكورة، ووجّه إعدادات Supabase Auth إلى نطاق النشر.
- CSV متاح مباشرة من شاشة الطلبات والتقارير ويمكن فتحه في Excel. يلزم إعداد مولّد PDF إذا أردت تقارير PDF منسقة.
